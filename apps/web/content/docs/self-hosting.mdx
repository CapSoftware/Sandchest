Sandchest is open source under the AGPL-3.0. You can run the whole product yourself: the dashboard, GitHub reviews, deep scans and fix checks. A self-hosted install has no billing and sends nothing to us.

The repository's README is the full guide. This page is the overview.

## What runs

`docker compose up` starts two containers:

- **web**: the Sandchest app. It serves the dashboard, receives GitHub webhooks and runs the scans itself. There is no separate worker.
- **postgres**: the database, which also keeps track of running scans.

Scans run on the same machine, each in its own temporary directory that is deleted when the scan ends. The code indexer ships inside the web image, for both `amd64` and `arm64`.

## What you need

- A machine with Docker.
- A public HTTPS address that GitHub can reach, for webhooks and sign-in.
- A model endpoint that speaks the standard chat-completions protocol. Sandchest is built for one class of model: fast, abliterated, with strict JSON-schema output, parallel tool calls and prompt caching.
- A GitHub account or organization to create your GitHub App on.

## Setting up

1. Clone the repository and copy `.env.example` to `.env`.
2. Point Sandchest at your model:

   ```bash
   LLM_BASE_URL=https://models.example.com/v1
   LLM_API_KEY=
   LLM_MODEL=
   ```

   The one model is used for every part of a scan. There are no per-provider settings.
3. Start it:

   ```bash
   docker compose up
   ```

4. Open `/setup` on your Sandchest address. It is protected by a setup token, so only you can use it. One click creates your own GitHub App through GitHub's app manifest flow, with the right permissions and webhook address already filled in.
5. Install your new App on the repositories you want scanned, sign in, and recon starts on each one.

## Optional settings

| Setting | What it does |
| --- | --- |
| `SMTP_URL`, `EMAIL_FROM` | Send emails about critical findings and finished deep scans through your mail server. Without them, no email is sent. |
| `AUTUMN_SECRET_KEY` | Leave it empty. Without it billing is off: no plans, no credits, nothing limited. |
| `LLM_PRICE_INPUT`, `LLM_PRICE_CACHED_INPUT`, `LLM_PRICE_OUTPUT` | Your model's prices, in US dollars per million tokens, so each scan records what it cost you. |

## Privacy

A self-hosted Sandchest has no telemetry and sends nothing to us. It connects to:

- **GitHub**, to read the repositories you installed it on and post reviews.
- **Your model endpoint**, for the scans themselves.
- **OSV** (osv.dev), the open vulnerability database, to look up your dependencies. Only package names and versions are sent.

Your code, findings and threat models stay on your machine and in your database.

## Keeping it safe

- Keep the setup token secret, and keep Sandchest behind HTTPS.
- Don't expose `/.well-known/workflow/v1/flow` to the internet. It is the internal endpoint that runs scans, and only the app itself should reach it.
- Scans read code from repositories you chose, but that code may still be hostile. Sandchest never runs it, and treats everything in it as untrusted.
